# Showing clients what changed: diagrams, notes and video

<p class="lead">Short guides for developers who have to show a non-technical client what a change does. They cover Mermaid diagrams, release notes, short update videos and Claude Code skills, using the explain-to-customer skill and the official docs of each tool as the source.</p>

## [Writing a Mermaid sequence diagram, from arrows to loops](/blog/mermaid-sequence-diagram)

Mermaid sequence diagram syntax with examples: participants, arrow types, activations, notes, loops, alt and par blocks, autonumber and a before and after pair.

## [A release notes template your clients will actually read](/blog/release-notes-template)

A release notes template for client updates: subject line, what changed, what they need to do, known limits, plus a Keep a Changelog version for developers.

## [Turning a Mermaid diagram into a PNG or SVG file](/blog/mermaid-to-png)

Convert a Mermaid diagram to PNG or SVG three ways: the Mermaid live editor, mermaid-cli (mmdc) with scale and background flags, and an automated skill run.

## [Getting a Mermaid diagram into Confluence or Google Docs](/blog/mermaid-diagram-confluence-google-docs)

How to put a Mermaid diagram into Confluence or Google Docs: paste a rendered PNG or SVG, or use a marketplace app, and where Obsidian and GitHub fit in.

## [Mermaid entity relationship diagrams, explained by example](/blog/mermaid-er-diagram)

Mermaid ER diagram syntax: entities, crow's foot cardinality, identifying relationships, attributes with PK and FK keys, plus state and flow diagram pointers.

## [Skills and plugins in Claude Code, and when you need which](/blog/claude-code-plugins-vs-skills)

Claude Code plugins vs skills: a skill is one SKILL.md folder, a plugin packages skills, agents, hooks and MCP servers. When to ship which, from the docs.

## [From pull request to a short product update video](/blog/product-update-video-from-pull-request)

Make a short product explainer video from a pull request: pick the story, capture real screenshots, write captions, render a 30 to 60 second MP4 locally.

## [Explaining a code change to a client who does not code](/blog/explain-code-changes-to-clients)

How to explain technical changes to a non-technical client: start from what they see, use their words, show before and after, say what they must do.

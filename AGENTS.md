# AGENTS.md

explain-to-customer is an agent skill for Claude Code that turns a code change into a short client-ready video, slides, diagrams and a message. Developers install it into Claude Code with `npx skills add`.

## Verify a change

No CI runs on pull requests. Only the Pages deploy runs, on `main`. Before pushing:

- `cd skills/explain-to-customer && node --test scripts/test/*.test.mjs`
- `node scripts/theme.mjs --validate` (from the same folder) checks every style against `styles/_schema.json`. It needs the tool workspace: run `node scripts/setup.mjs` once (about 250 MB, installed into `~/.cache/explain-to-customer`), or `node scripts/setup.mjs --dry-run` to see what is missing.
- Docs: `npm ci && npm run docs:build` from the repo root, on Node 22 as in the deploy workflow.

## Gotchas

- The skill is `skills/explain-to-customer/`, and `SKILL.md` is what Claude Code loads. Users install it from `main` with no release step, so a merge reaches them on their next `npx skills update`.
- `SKILL.md` pre-approves only the bare command `node "${CLAUDE_SKILL_DIR}/scripts/<script>.mjs"`. A new script has to fit that pattern, and instructions must run each script as its own command, with no `&&`, pipes or `cd`.
- The skill treats the user's project as read-only. Scripts write only into the chosen output folder and the tool workspace.
- Rendering tools are not bundled. `scripts/setup.mjs` installs pinned versions (`PINNED`) into the tool workspace, so bump them there, not in a package.json.
- The root `package.json` is the private docs package only (VitePress). Its `overrides` pins `vite` for security advisories, so keep it when updating dependencies. Dependabot opens weekly npm and Actions PRs.
- The docs read `skills/explain-to-customer/styles/` relative to the current directory (`docs/.vitepress/theme/styles.data.ts`), so build from the repo root. Changes to styles also trigger a docs deploy.
- `skills/explain-to-customer/styles-preview.png` is generated by `node scripts/styles-preview.mjs`. Regenerate it after changing a style.
- `docs/public/` also holds the README's images and logo. Renaming a file there breaks the README.

## Conventions

- Commit subjects use conventional-commit style, in English, with no body or trailer.
- Work on a branch and open a PR. The owner merges.
- Don't add emoji to new text. Code comments are short, one line where possible, and explain why. Format scripts with `npx prettier --write "scripts/**/*.mjs" "templates/scenes/*.{js,css}" "styles/*.json"` from the skill folder.
- The README follows the owner's template. Leave every image from `halitsever-api.vercel.app` byte-for-byte as it is. Only the `title=` value of `api/repo-title` and the issue wrapper link may be corrected.
- Style names only describe what inspired them. Don't add logos, trademarks or proprietary fonts.

## Docs site

- The VitePress site lives in `docs/` and deploys to https://projects.halit.org/explain-to-customer/ from `.github/workflows/deploy-docs.yml` on pushes to `main` that touch `docs/`, the root package files, the styles or that workflow.
- A new guide page goes into the sidebar in `docs/.vitepress/config.mts` and into `docs/public/llms.txt`.
